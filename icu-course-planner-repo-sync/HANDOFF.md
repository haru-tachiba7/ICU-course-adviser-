# 引き継ぎ資料 — ICU履修計画アプリ「履修台帳」

作成日: 2026年10月4日。次の会話でこのプロジェクトを再開するときに、まずこのファイルを読めば
経緯と現状が分かるようにまとめたもの。技術的な詳細(関数の役割など)は `CODEMAP.md`、
使い方やデータ更新手順は `README.md` を参照。

## 1. プロジェクトの経緯

1. もともとICU(国際基督教大学)の4年間の履修計画を、ChatGPT + Notionで管理していた。
   Notion側にはCourse Master(科目マスター)・Course Plan・Term Plan・Graduation Requirements
   という4つのデータベースを作り、GE科目84件を含む多数の科目データを手作業で蓄積していた。
2. 「イメージに近いものを作りやすい」という理由でClaudeに移行。
3. 友人とのアプリ開発に統合する可能性が出てきたことをきっかけに、Notion運用から
   **ブラウザで動く独立したWebアプリ**への全面移行を決定。データの持ち方も検討した結果、
   Notion APIではなく**独自データベース(静的JSファイル)**に一本化する方針にした。
4. ICU公式サイト(`campus.icu.ac.jp`)から科目データを取得し、Gitリポジトリとして管理、
   GitHub Pagesで公開するところまで実現した。
5. 当初「コードは書けない」とのことで実装は全面的にClaudeが担当していたが、
   **現在は本人がコードを直接書き換えていく方針に変わっている**。

## 3. リポジトリの構成

```
index.html                     アプリ本体(CSS+HTML+JS)
data.js                        科目カタログ(739科目、全件に概要つき)・卒業要件の規定値
cap_rules.js                   単位上限ルール(一般教育・保健体育の余剰単位)
majors.js                      全30メジャー一覧・ELAストリーム別必要単位
README.md                      使い方・データ更新方法
CODEMAP.md                     コードの構成リファレンス(関数一覧など)
HANDOFF.md                     このファイル
scripts/
  parse_search_results.py      SearchCourseAndSyllabus.aspx保存HTML → data.js(科目データ本体)
  parse_coursedesc.py          CourseList.aspx保存HTML → data.jsのdesc(概要)欄
  build_single_file.py         上記3つのjsをindex.htmlに埋め込み、Claudeアーティファクト公開用の
                                1ファイル版(dist_single_file.html、コミット対象外)を作る
```

ICU公式サイトには外部から直接叩けるAPIが無く、`SearchCourseAndSyllabus.aspx`も`CourseList.aspx`も
ページ送り・メジャー切り替えがJavaScriptのpostbackで行われるため、**データの取得・更新は
「本人がブラウザで該当ページを開いて保存 → Claudeがパースしてdata.jsに反映」という半手動の運用**になっている。
1科目ずつのシラバス詳細(`PreviewSyllabus.aspx?regno=...`)だけは単純なURLなので、Claudeが直接取得できる。

## 4. 実装済みの機能

### データ
- 2026年度・全学期・全メジャーの科目739件を取得済み(`SearchCourseAndSyllabus.aspx`の
  「Results: ALL」表示を保存してパース)
- 739件**全件に授業概要(`desc`)を取り込み済み**。GE・ELA・JLPは`CourseList.aspx`の保存HTMLから、
  残り(全メジューの専門科目・保健体育・世界の言語・教職課程など)は一括で取り込んだ
- 単位表記の揺れ(`"(6)"`「複数学期合計」、`"3/(9)"`「卒業研究」、`"1/3"`「PEエクササイズ」)を
  正しく数値化する`parseCredit`で対応済み

### 卒業要件まわり
- 公式資料「2026年度入学者 ディプロマ・ポリシー及び卒業要件(ELA履修対象生向け)」を入手し、
  その数値をすべて実装に反映済み(語学・一般教育・保健体育・基礎科目・専攻科目・卒業研究・選択科目)
- **履修形態を「メジューのみ／ダブルメジャー／メジャー・マイナー」から選べる**。選んだ形態に応じて、
  専攻科目が1本(21単位)か2本(21+30、または21+15)かが自動的に切り替わる
- 基礎科目の「メジャーから最低6単位」、ダブルメジャーの「メジャー2のうち300番台を最低3単位」を、
  実際の履修データから計算して警告表示
- 一般教育・保健体育の必修超過分のうち、選択科目に算入できる単位数(上限9/2)を実数値で表示
- ELAストリーム(1〜4)を選ぶと、公式資料通りに英語(ELA)・選択科目の必要単位が自動設定される
  (履修形態ごとに数値が違う点も反映済み)
- 必要単位の数字は直接クリックして手動上書きも可能(JLPなど、まだ自動化していない部分の逃げ道)

### 科目の閲覧・追加
- 全30メジャーから選択可能。区分(基礎科目/専攻科目/選択科目)はメジューの科目番号の接頭辞と
  百の位から実行時に自動判定(`courseCategory`関数)。データ自体はメジャーに依存しない
- 科目タイトルをクリックすると、概要・開講情報(学期ごとの担当教員・時間割)・公式シラバスへの
  リンクを展開表示
- 検索窓、区分フィルタ、メジャーフィルタで絞り込み可能
- 「追加時の状態」(履修済/履修中/予定/検討中)を選んでおき、「＋」ボタン一つで即座に履修リストへ
  追加(モーダルなし)。追加直後は取り消しトーストが出る。履修リスト側で状態を後から変更することも可能

### オンボーディング
- 初めてサイトを訪れた人向けに、5ステップのスポットライト式チュートリアルを実装
  (履修形態・メジャー設定 → 卒業要件の見方 → 余剰単位の見方 → 科目追加の仕方 → 検索・絞り込み)
- 右上の「使い方」ボタンからいつでも見返せる

## 5. 未対応・既知の制約

- JLPの必要単位は公式資料にある変動(最小12単位になるケースなど)を反映しておらず、手動編集頼り
- シラバスの詳細(評価方法・週別の授業内容など)は未取り込み。今あるのは概要(`desc`)のみ
- 興味度に基づく推薦ロジックは未実装(Notion時代に84件のGE科目に入力していた興味度データも、
  今回は引き継いでいない)
- Co-Listing科目(他メジャーの科目を自分のメジャーの基礎科目・専攻科目として計上できる特例)は未対応
- メジャー1とメジャー2(またはマイナー)に同じメジャーを選んでも警告が出ない
- メジャー固有の追加要件(300番台最低3単位はダブルメジャー共通のルールとして実装済みだが、
  メジャーごとに異なる個別要件があれば未反映)
- 友人のアプリとの統合は、現状「将来の拡張」として保留したまま具体的な設計はしていない
